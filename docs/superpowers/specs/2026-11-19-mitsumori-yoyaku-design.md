## 空き枠の決め方（yoyaku GET）

- 期間：明日〜28日後（日本時間）。枠：各日 8:00〜16:00 の毎時ちょうど、長さ1時間
- カレンダーを events.list（singleEvents）で読む
  - 時刻のある予定：「予定なし（transparent）」以外はふさぐ。枠の前後30分にかかったら出さない
  - 終日の予定：その日を丸ごと出さない（transparent でも）
  - キャンセル済み（status=cancelled）は数えない
- Firestore の yoyakuWaku（仮予約の錠）がある枠も出さない（カレンダーへの書き込みが遅れた瞬間の保険）
- 返すのは「日付 → 空いている始まりの時刻の並び」だけ。予定の中身は返さない

## 仮予約（yoyaku POST）

1. 形を確かめる：作業（料金表の名前・1〜8個）・日付と時刻が上の枠にある・市が5択・各選択肢が決まった言葉・お名前1〜40字・連絡が line/denwa・電話なら番号の形・ひとこと500字まで・隠し欄（人には見えない入力欄）が空
2. 数を確かめる：同じ送り元（IPを塩つきで縮めた値）から今日3件まで・全体で今日10件まで
3. その枠がまだ空いているか、カレンダーをもう一度読む
4. トランザクションで yoyakuWaku/{日付T時刻} を作る（あれば「先に埋まりました」）
5. カレンダーに予定を入れる。題名に「フッ軽」「予約カレンダー」を入れない（syncFromCalendar と writeCalendarEventsToSheet が拾うため）。extendedProperties.private.yoyakuId を付ける
6. yoyaku/{id} を書く（status: kari、番号4桁、eventId）
7. 中元さんの LINE に知らせる・管制に通知
8. 返す：番号・日時の文字・LINE で送る文
- 5 で失敗したら 4 の錠を外して「受け付けられませんでした。お電話かLINEで」

## 確定・お断り（yoyakuKotae、requireAdmin）

- 確定：予定を読み直し（中元さんが動かしていればその時刻）、題名の「【仮】」を外す。yoyaku を kakutei に。返す：今の日付・時刻・行に入れる中身
- 管制がそのあと appendSheetJob を呼ぶ（date＝受けた日、workDate＝見積もりの日、time、type「予約」、status「未対応」、memo「HPの見積もり予約・カレンダーから自動」）。メモに「カレンダーから自動」が無いと、シート→カレンダーの写しが同じ予定をもう1つ作る
- お断り：予定を消す・錠を消す・yoyaku を kotowari に

## お客様の画面（/yoyaku/）

- Vite の2つ目の入口（`yoyaku/index.html` → `src/yoyaku/main.tsx`）。トップの組み立て（SSR）には入れない
- 上：「今日・急ぎの方」電話・LINE の2つ
- 手順4つ（作業 → 日時 → 場所と様子 → お名前と連絡の受け方）→ 送る → 済みの画面
- 作業の名前は `components/Services.tsx` の groups（hidden を除く）から読む。写しを作らない
- LINE で送る：`https://line.me/R/oaMessage/%40200rcmxs/?{文をencodeURIComponent}`。友だちでない方の見え方は未確認（仮ページで確かめる）
- 呼び先の関数の住所：`https://asia-northeast1-fukkaru-app.cloudfunctions.net/yoyaku`
- 受け付ける呼び元（CORS）：本番・fukkarulp.web.app・仮ページ（fukkarulp--*.web.app）・localhost

## 守ること

- 関数を出すのは1本ずつ `--only functions:admin:yoyaku` → `functions:admin:yoyakuKotae`。出す前に中元さんに一言
- お名前・電話は Firestore（管制だけが読める）と中元さんのカレンダーだけ。ログには件数と番号だけ
- firestore.rules：yoyaku は管制だけ読める・書けるのは関数だけ。yoyakuWaku は誰も読めない
- 試しの予約は、カレンダー・Firestore・シートの行まで消す（シートの行は書く前の中身に戻す）
